# 修复计划：AML 硬件路径 RGB_OSD 标志导致 HDR PGS 字幕发绿

## 背景

设备走 **AML 窗口系统 + 硬件 OSD 路径**（`WinSystemAmlogic` + `CRendererAML`），GLES per-element shader 方案（`KODI_TRANSFER_PQ`、`SM_TEXTURE_NOBLEND_HDR_PGS_PQ_OUTPUT`）**不生效**。发绿是内核硬件路径的 bug。

## 根本原因

```
播放 DV 内容 + SDR 显示器:
  → RendererAML::Configure 设 osd1_hdr_mode=0 (SDR 显示器 IsHDRDisplay()=false，正确)
  → 内核 set_hdr2_v0.c::hdr_func() 判断 RGB_OSD 标志:
      is_amdv_on()=true (DV 激活)
      osd1_hdr_mode=0
      osd_pq_bypass=0
      → line 3193 三个条件全 false → RGB_OSD 不设置 ❌
  → OSD1 HDR core 用 identity 矩阵 (bypass_coeff)
  → OSD 的 RGB 数据直通到 blender
  → blender/显示管线把 RGB 当 YUV 读 → 发绿/发紫
```

**核心矛盾：** `RGB_OSD` 默认触发条件是 `!is_amdv_on()`（DV 关闭时）。DV 内容播放时 `is_amdv_on()=true`，条件不满足；而 `osd1_hdr_mode=0`（SDR 显示器该设 0）、`osd_pq_bypass=0` 也没触发 → RGB_OSD 不设置。

## 修复方案（2 处）

### 1. 内核 common_drivers `set_hdr2_v0.c` — 补第二个 `hdr_func` 副本的 RGB_OSD 条件

文件：`/home/greatwall/common_drivers/drivers/media/enhancement/amvecm/set_hdr2_v0.c`

```c
// line 5516 当前:
if (!is_amdv_on())
    hdr_process_select |= RGB_OSD;

// 改为（与第一个副本 line 3193 一致）:
if (!is_amdv_on() || osd_pq_bypass || osd1_hdr_mode)
    hdr_process_select |= RGB_OSD;
```

**为什么改第二个副本：** 文件里有**两个** `hdr_func` 副本。第一个（line 3193）已加 `|| osd_pq_bypass || osd1_hdr_mode`，第二个（line 5516）只检查 `!is_amdv_on()`，漏了这个条件 → 导致 `osd_pq_bypass=1` `/` `osd1_hdr_mode=1` 在这个路径下不生效。

### 2. xbmc `RendererAML.cpp` — 用 `osd_pq_bypass` 而非 `osd1_hdr_mode` 触发 RGB_OSD

文件：`/home/greatwall/xbmc/xbmc/cores/VideoPlayer/VideoRenderers/HwDecRender/RendererAML.cpp`

在 `Configure()` 中 `osd1_hdr_mode` 写入之后，加：

```cpp
// DV 内容播放时，确保 OSD RGB 数据被标记为 RGB，
// 防止 blender 误读为 YUV 导致颜色错乱。
// osd_pq_bypass 只设置 RGB_OSD 标志 + LUT bypass，不改变 OSD 亮度。
bool dv_active = (picture.hdrType == StreamHdrType::HDR_TYPE_DOLBYVISION);
CSysfsPath("/sys/module/aml_media/parameters/osd_pq_bypass", dv_active ? 1 : 0);
```

**为什么用 `osd_pq_bypass` 而非 `osd1_hdr_mode`：**
- `osd1_hdr_mode=1` → 设 RGB_OSD + 做 SDR→HDR **亮度转换**（过量，颜色错乱）
- `osd_pq_bypass=1` → 只设 RGB_OSD + LUT bypass（**不改亮度**）

正好满足"要 RGB 标记、但不要转亮度"的需求。

## 不需要改动的

- GLES shader 那套（`gles_shader_texture_noblend.frag`、`convertHdrPgsForPqOutput`、`GetOverlayTextureShaderMethod`）— AML 硬件路径不走
- SDR tone mapping 变体（`KODI_HDR_PGS_SDR_OUTPUT`）— 多余设计，可后续清理
- `precision` 精度改动 — 已 revert

## 关键文件确认

- `/home/greatwall/common_drivers/drivers/media/enhancement/amvecm/set_hdr2_v0.c`（line 5516 处）
- `/home/greatwall/xbmc/xbmc/cores/VideoPlayer/VideoRenderers/HwDecRender/RendererAML.cpp`（Configure 中）
- sysfs 正确路径：`/sys/module/aml_media/parameters/osd1_hdr_mode` + `osd_pq_bypass`（set_hdr2_v0.c 编译进 aml_media 模块）

## 验证

1. 编译内核模块 + xbmc
2. SDR 显示器播放 DV 影片：GUI 和 Sub 颜色正常（不发绿、不发紫）
3. 日志/`cat /sys/module/aml_media/parameters/osd_pq_bypass` 确认 = 1
4. HDR 显示器播放 DV 影片：不受影响（原有 `osd1_hdr_mode` 机制继续工作）
5. 确认修复后不再需要强制 `osd1_hdr_mode`（保持 SDR 显示器的 0 值）
